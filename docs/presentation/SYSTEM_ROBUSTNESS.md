# Remini 시스템 강건성 설계 (System Robustness)

> **한 줄 요약**: 시스템도 안 죽고, 어르신 말도 다 알아들음.

---

## 두 가지 위협 — Remini가 견뎌야 하는 것

```
위협 1. 시스템 외부 실패              위협 2. 사용자(환자) 발화 불완전
   - LLM 응답 안 옴                       - "어어… 음… 그…" 어버버
   - DB 연결 끊김                          - "거시기", "저시기" 사투리·대명사
   - TTS 모델 로드 실패                    - 30턴 중간에 발음 끊김
   - Webhook 타임아웃                      - "그 사람", "거기" 모호한 지시어
        ↓                                       ↓
   "오류 허용 설계"                        "모호 발화 처리"
   (Fault Tolerance)                       (Disfluency Tolerance)
```

치매 환자 대상 시스템이라 **양쪽 모두** 흔하게 일어남 → 둘 다 대비 필요.

---

## 위협 1 — 오류 허용 설계 (시스템이 죽지 않게)

### 핵심 원칙
> **"비차단(non-blocking) 실패 + 폴백 우선 → 대화 흐름 절대 끊지 않는다"**

### 7가지 방어선

**① 외부 호출 다 try/except + timeout 걸림**
```
Ollama LLM       180초 timeout
입력 분류 LLM     2초 timeout
Caregiver webhook 5초 timeout (실패해도 본 흐름 영향 X)
TTS 음성 복제    120초 timeout
```
어떤 외부 호출도 무한 대기 X.

**② 폴백 체인 — 메인 실패하면 백업 발동**
```
TTS:   음성 복제 → Qwen3 → Supertonic → MMS  (4단계)
분류:  LLM → 키워드 휴리스틱                  (2단계)
검색:  벡터 DB → 토큰 매칭                    (2단계)
디바이스: CUDA → CPU                          (자동)
```
완전 실패 = 거의 불가능.

**③ 헬스체크 & Ready 플래그**
```
GET /health          → AI 서버 상태
checkNeo4jConnection → DB 상태
_db_ready 플래그     → DB 사용 불가 시 자동 우회
_load_failed 플래그  → 모델 로드 실패 캐싱 (재시도 안 함)
```

**④ Graceful Degradation — 부분 실패 허용**
```
Warmup 실패해도 서버 시작 계속
VAD 실패해도 다음 블록 처리
DB 못 쓰면 메모리(JSON)만 저장
음성 프로필 미등록이면 speaker verify 자동 통과
```
일부 기능 죽어도 전체 시스템은 작동.

**⑤ 데이터 복구 — 우리가 직접 만든 것**
- **메모리 파일 손상 자동 복구**: `memory_store.py`의 `_salvage()` 함수가 JSON 깨졌을 때 백업 만들고 유효 항목만 추출
- **원자적 저장**: temp 파일 → fsync → os.replace, race condition 방지

**⑥ Crisis Guardrail — 우선순위 차단**
```
환자 발화 → 자해/자살 키워드 감지 → LLM 호출 전에 차단
                              → 고정 안전 응답만 발사
                              → 보호자 webhook 즉시 알림
```
LLM이 잘못된 응답할 위험 자체를 제거.

**⑦ 비차단 알림**
- 보호자 webhook은 별도 태스크 (fire-and-forget)
- 실패해도 환자 대화엔 영향 없음

### 대표 예시 — TTS 4단계 폴백

```
환자: "오늘 뭐 했어?"
   ↓
LLM: "산책 다녀오셨나봐요"
   ↓
음성 합성 시도
   ┌── ① 환자 가족 목소리 복제   → 실패 (서버 다운)
   ↓
   ┌── ② Qwen3-TTS                → 실패 (CUDA OOM)
   ↓
   ┌── ③ Supertonic                → 실패 (모델 로드 실패)
   ↓
   ┌── ④ MMS (Meta 다국어 TTS)    → 성공 ✅
   ↓
환자에게 음성 출력 (대화 안 끊김)
```

### 약점 (정직하게)
- Retry/backoff 거의 없음 (실패 = 즉시 폴백)
- Circuit breaker 없음 (플래그 단순 차단만)
- 큐 가득 차면 drop (재시도 X)

## 위협 2 — 모호 발화 처리 (어르신 말 다 알아듣게)

### 핵심 원칙
> **"교정하지 않는다. 단서만 모아서 LLM에 힌트로 넘긴다."**

치매 환자 발화는 어버버·반복·생략·사투리가 정상. 우리 시스템은 이를 **고치려 하지 않고** 흐름을 따라감.

### 3계층 설계

**계층 1 — STT가 발화 불완전성 허용**
```
VAD 침묵 허용:    800ms  (어르신 생각 시간 길어도 안 끊음)
최소 발화 길이:   300ms  (기침/잡음 무시)
Whisper:          large-v3, 한국어 명시
조각 발화:        여러 토막을 한 턴으로 누적
```

예: "어어… 철… 철수가… 밥…" — 일반 시스템은 4번 턴으로 쪼개지만 우리는 한 턴으로 묶음.

**계층 2 — 사투리·간투사 정규화**

5개 지역 사투리 매핑 사전 (`dialect.py`):
```python
"거시기" → "그것"   # 전라도
"묵었나" → "먹었어" # 경상도
"잉"     → ""       # 전라도 어미
"부러"   → "요"     # 전라도
"카더라" → "한다고 해" # 경상도
```

주저 토큰 패턴 (`retrieval.py`):
```python
"으어", "음", "그", "저", "..." → 자동 감지 → 조각 발화로 판정
```

**계층 3 — KG 기반 대명사 해소** ★ 핵심

조각 발화 감지하면 환자의 개인 지식 그래프(가족·장소·반려동물)에서 후보 단어 매칭 → LLM에 힌트로 주입:

```
환자 발화: "으어… 철… 철수가… 강아지 밥…"
              ↓
          조각 감지
              ↓
   환자 KG 검색 (Neo4j)
              ↓
   매칭: 철수(손자), 뽀삐(반려견)
              ↓
   LLM에 힌트 주입:
   "[STT 조각 재구성 힌트]
    환자 발화: '으어… 철… 철수가… 강아지 밥…'
    참고 기억 단서: 철수(손자), 뽀삐(반려견)
    이 단서를 자연스럽게 활용해 이야기를 이어가세요."
              ↓
   LLM 응답:
   "철수가 뽀삐 밥 챙기고 있는 모습이 떠오르시나봐요.
    그 모습이 어떠셨어요?"
```

### 추가 보강 — 대화 컨텍스트 누적

**최근 대화 윈도우** (`agent.py`)
- 최근 8턴 메시지 + 최근 10턴 요약을 매번 LLM에 전달
- "그 사람", "거기" → 직전 턴의 인물명·장소로 자동 해소

**입력 분류 5종** (`input_classifier.py`)
- "혼란·망상형" 감지 시 → "감정 공감 + 긍정 기억 전환" 지침 자동 주입
- LLM 분류 실패하면 키워드 휴리스틱 폴백

### 시스템 프롬프트의 기본 정책 (`llm.py`)

```
"환자가 사실과 다른 말을 해도 교정하지 않습니다.
 '그랬군요' 하고 흐름을 따라갑니다."

"참고 기억에 없는 내용은 단정하지 않고 부드럽게 확인합니다."

"5W 심문식 질문 금지. 1H(어떤 느낌?) 중심."

"같은 질문을 반복해 환자를 시험하지 않습니다."

"'그것도 몰라요?' 같은 수치심 표현은 사용하지 않습니다."
```

이 정책이 fine-tune으로 모델에 내재화됨 (Stage 1 SEED 프롬프트).

## 두 위협 통합 — Remini 시스템의 강건성

| | 위협 1 (시스템 실패) | 위협 2 (발화 불완전) |
|---|------------------|------------------|
| **누가 망가지나** | 외부 시스템 | 환자 발화 |
| **핵심 원칙** | 비차단 + 폴백 | 교정 X + 단서 추출 |
| **대표 기법** | 4단계 TTS 폴백 | KG 기반 대명사 해소 |
| **데이터 자체 보호** | _salvage() 자동 복구 | dialect 매핑 사전 |
| **안전망** | Crisis Guardrail (LLM 전 차단) | 시스템 프롬프트 (교정 금지 룰) |
| **결과** | 대화 안 끊김 | 어르신 말 다 알아듣음 |

## 발표 멘트

> "Remini는 두 종류의 비정상 상황을 동시에 견디도록 설계되었습니다. 외부 시스템 실패 시에는 7가지 방어선(try/except, 4단계 폴백, 헬스체크, graceful degradation, 자체 데이터 복구, crisis guardrail, 비차단 알림)으로 대화를 끊지 않습니다. 환자 발화가 불완전할 때에는 교정하지 않고 STT 누적 + 사투리 정규화 + KG 기반 대명사 해소의 3계층으로 단서를 모아 LLM에 힌트로 넘깁니다. 두 설계 모두 '대화 흐름을 절대 중단하지 않는다'는 단일 원칙에서 출발합니다."
