# Remini 회상요법 도메인 CAG 컨텍스트

이 디렉토리의 마크다운 파일들은 **AI 서버 시작 시 자동으로 합쳐져 LLM 시스템 메시지로 통째 주입**됩니다 (Cache-Augmented Generation, Chan et al., arxiv 2412.15605).

## 작동 방식

```
ai-server 시작
  ↓
docs/cag/*.md 알파벳 순으로 모두 로드
  ↓
하나의 큰 텍스트로 합침 → 시스템 메시지 #2 로 주입
(시스템 메시지 #1 = ai-server/app/services/llm.py 의 SYSTEM_PROMPT — 안전·화법·형식 하드 룰)
  ↓
Ollama KV 캐시가 prefix(하드 룰 + 도메인 컨텍스트)를 잡음
  ↓
이후 모든 환자 턴에서 추가 prefill 비용 ≈ 0
```

도메인 컨텍스트는 모든 환자에게 공통 노출됩니다. 환자 개인의 기억·일화는 여기가 아니라 AuraDB(메모리 시스템)로 관리됩니다.

**왜 CAG 인가**: 도메인이 좁고 정적 (회상요법 임상 도서 16권 핵심 패턴). 발화별 검색 (RAG) 없이 한 번 prefix prefill 만으로 모든 환자 턴 amortize. 학술 인용: Chan et al., "Don't Do RAG: When Cache-Augmented Generation is All You Need for Knowledge Tasks", arxiv 2412.15605.

## 자료 추가 규칙

1. **포맷**: 마크다운 (`.md`). docx/pdf/txt는 변환해서 넣으세요. (요청하면 변환 도와줌)
2. **순서**: 파일명 prefix `00_`, `01_`, `02_` ... 로 로드 순서를 정합니다. 큰 그림 → 디테일 순으로 배치 권장.
3. **제외 규칙**:
   - `_` 로 시작하는 파일은 자동 제외 (작업 메모용).
   - `README.md` 는 자동 제외.
4. **반영**: AI 서버 재시작 시 자동 반영. uvicorn `--reload` 모드면 파일 저장만 해도 다음 요청부터 적용.

## 들어가면 안 되는 자료 (안전 가드)

- ❌ 환자 개인 식별 정보 (이름·전화번호·주소·진단명) — 그건 AuraDB로
- ❌ 시스템 설계·아키텍처·API 문서 — 도메인 컨텍스트는 "환자와 어떻게 대화할지"만
- ❌ 임상가가 아닌 사람이 단정해선 안 되는 의학 진단·처방·약 복용 지시
- ❌ 특정 종교·정치적 입장 — 환자 다양성 침해

## 분량 가이드

- 합산 **30k 토큰 이하 권장** (한국어는 char/1.88 ≒ 토큰 추정).
- 현재 합산 ≈ **26.8k 토큰** (실측, gemma4:31b 토크나이저).
- gemma4:31b 기준 `OLLAMA_NUM_CTX=32768` 환경에서 도메인 컨텍스트 + 환자 메모리 + 대화 이력 + 응답 모두 안전하게 들어감 (82% 활용, 여유 18%).
- gemma4:31b 의 모델 본래 한계는 **262,144 (256k)**. 64k / 128k 로 확장 가능하나 cold prefill 시간·KV cache 메모리 trade-off 고려.
- 50k 토큰을 넘기면 attention dilution 위험이 커지므로, 그 시점엔 RAG(임베딩 검색)로 전환을 검토하세요.

## 디버깅

- 도메인 컨텍스트가 실제로 주입되고 있는지 확인: `curl localhost:8000/health` 또는 LLM 응답에 도메인 단서(예: "원삼저고리", "댕기")가 자연스럽게 등장하는지 관찰.
- 자료 변경이 반영 안 되면 ai-server 재시작 (`bash restart.sh`).
