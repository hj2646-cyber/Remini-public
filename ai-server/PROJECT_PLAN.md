# 치매 환자 회상요법 지원을 위한 개인화 대화 시스템 (Remini-AI / MemorIE) 통합 계획서

**캡스톤 최종 통합본 · 발표/보고서 기준 문서 · 다른 LLM 전달용 정리본**

## 문서 목적

- 기존 기획서, 수정본, 교수님 오리엔테이션, 회의록, 발표자료, 피드백 문서를 하나의 최종 계획서로 통합한 버전이다.
- 사용 목적은 캡스톤 계획서/발표 기준 문서이면서, 다른 LLM에 넣어도 핵심 구조를 바로 학습할 수 있는 정리본을 만드는 것이다.
- 상충하는 내용이 있을 경우에는 **후반부 교수 피드백과 한 학기 구현 가능성**을 우선하여 정리했다.

## 1. 최종 프로젝트 정의

본 프로젝트의 공식 표현은 '치매 환자 회상요법 지원을 위한 개인화 대화 시스템'이다. '치료', '완치', '진단'이라는 표현은 사용하지 않으며, 시스템의 역할은 비약물적 중재를 지원하는 대화 도구로 한정한다.

핵심 목표는 환자의 생애기억과 현재 일상 정보를 활용해 회상 대화를 지속적으로 유도하고, 발화가 불완전하더라도 문맥을 바탕으로 대화를 끊기지 않게 복구하며, 보호자가 대화 정책을 간접 조정할 수 있는 프로토타입을 구현하는 것이다.

산업공학적 관점에서 본 프로젝트는 인간공학, 인지공학, 시스템공학, 안전공학, 공학통계 및 실험계획법을 종합적으로 적용하는 캡스톤 과제다. 즉, 단순한 챗봇 구현이 아니라 '사용자 특성에 맞는 시스템 설계 + 위험 통제 + 검증 프로토콜'까지 포함해야 한다.

### 1-1. 문제 정의

| 현재 상태(S1) | 목표 상태(S2) | 핵심 GAP |
| --- | --- | --- |
| 돌봄 인력 부족, 회상요법의 인력·비용 부담, 환자별 생애기억 데이터의 비체계성, 명령어 기반 시스템의 높은 인지부담 | 환자별 기억과 현재 상태를 반영한 지속적 회상 대화, 안전한 응답, 개인맞춤형 인지·정서 지원, 검증 가능한 시스템 구조 | 현재는 환자의 과거 경험을 안정적으로 활용하면서도 안전하게 대화하는 시스템이 부족하다. 따라서 개인화 정보와 안전 통제를 갖춘 대화형 지원 시스템이 필요하다. |

### 1-2. 산업공학과의 연결

| 산업공학 영역 | 본 프로젝트에서의 역할 |
| --- | --- |
| 인간공학/HCI | 고령 사용자의 낮은 인지 여유를 고려해 복잡한 조작과 호출어 의존을 줄이고, 쉽게 참여 가능한 대화 흐름을 설계한다. |
| 인지공학 | 기억 특성, 주의 집중, 발화 오류, 정보 제시 방식, 좌절감 유발 요소를 함께 고려한다. |
| 시스템공학 | 환자, 보호자, 데이터베이스, LLM, 필터링 모듈의 상호작용을 하나의 폐루프 시스템으로 설계한다. |
| 안전공학 | 위험 발화 차단, 개인정보 보호, 망상 동조 방지, 의료적 판단 금지 같은 운영 가드레일을 둔다. |
| 공학통계/실험계획법 | 2x2 비교실험, 범주형 응답 라벨링, 정확도·정밀도·재현율·안전위반률을 통해 품질을 검증한다. |

## 5. 통합 시스템 설계

### 5-1. 전체 프레임워크

| 단계 | 내용 |
| --- | --- |
| 1. 입력 수집 | 초기 설문, 보호자 입력, 기존 기록, 대화 로그, 선택적 음성 입력을 수집한다. |
| 2. 개인화 정보 구조화 | 생애기억 DB와 일상루틴 DB로 분리 저장한다. 그래프 구현이 어렵다면 관계형/JSON 구조로 대체할 수 있다. |
| 3. 사전 분류와 검색 | 입력 발화를 회상 유도형, 일상 확인형, 위험/민감 주제형 등으로 분류하고 관련 정보를 검색한다. |
| 4. LLM 응답 생성 | 시스템 프롬프트, 검색 결과, 안전 태그를 함께 주입해 환각과 위험 응답을 줄인다. |
| 5. 출력 검토 | 생성된 응답을 다시 규칙 기반으로 검사하여 금지 문장이나 민감 정보 노출 여부를 확인한다. |
| 6. 로그·피드백 환류 | 대화 결과와 보호자 피드백을 저장해 다음 대화 정책과 개인화 정보를 갱신한다. |

### 5-2. 이원화 개인화 정보 구조

### 5-3. LLM 내부 처리 스키마

| --- | --- |

| 사용자 입력 | 환자 발화 원문(또는 텍스트), 입력 분류 결과, 위험 태그, 현재 대화 맥락 |

| 응답 생성 규칙 | 환자 수준에 맞는 짧고 명료한 문장, 긍정적 회상 유도, 필요 시 화제 전환, 낮은 확신 시 단정 회피 |
| 출력 제약 | 개인정보·금융정보·비밀번호 언급 금지, 진단/복약지시 금지, 공격적 정정 금지, 허위 기억 창작 금지 |

### 5-5. 다층 안전 가드레일

| 안전 계층 | 역할 |
| --- | --- |
| 1계층 규칙 기반 필터 | 입력/출력 단계에서 민감정보, 폭력·자해 표현, 금융정보 요청, 의료 지시 요청, 망상 강화 표현을 사전 차단한다. |
| 2계층 시스템 프롬프트 통제 | LLM이 반드시 지켜야 할 말투, 금지 응답, 회상요법 범위, 사실 기반 원칙을 명문화한다. |
| 3계층 피드백/스크리닝 | 보호자 피드백이나 별도 분류기를 통해 위험 대화, 반복 불만족 주제, 금지 주제를 후속 대화에서 조정한다. |

| 주 구현 경로 | 로컬 Qwen 계열 모델(가용 자원에 따라 14B~32B 범위) + 개인화 DB + 가드레일 |
| 비교 기준 | 상용 LLM(GPT/Gemini급) + 동일한 프롬프트/동일한 테스트셋 |
| 한국어 특화 대안 | 접근 가능한 경우 HyperCLOVA X를 한국어·문화맥락 강화 옵션으로 검토 |
| 선정 기준 | 한국어 응답 품질, 비용, 개인정보 보호, 로컬 구동 가능성, 시스템 통합 편의성 |

### 6-2. 구현 범위

| 구분 | 내용 |

| 우선 확장 | STT/TTS, 간단한 보호자 웹/앱, 기본적인 AI 주도 대화 시작(시나리오 기반), 대화 로그 저장 |
| 선택 확장 | 비전센서, 사진/영상 표시, 감정 분석, 감성 일기 자동 생성, 유튜브 연동 |
| 제외/비목표 | 임상 효능 입증, 의료 진단/처방, 완전 자율형 스마트홈 시스템, 파운데이션 모델 자체 학습 |

| 지식그래프 구현 난도가 높음 | 노드-관계형 JSON/CSV 또는 관계형 DB로 축소하되, 생애기억/일상루틴의 이원 구조는 유지한다. | 검색 논리와 비교실험은 유지 가능 |
| 선제적 센서 기능 구현이 지연됨 | 자동 감지 대신 시간 기반/버튼 기반/시나리오 기반으로 대화 시작 기능을 단순화한다. | 핵심 가치인 회상 유도와 검증은 유지 가능 |
| 보호자 앱 완성도가 낮음 | 웹 기반 입력 페이지와 로그 뷰어 수준으로 축소한다. | 피드백 반영 구조는 최소 수준으로 유지 가능 |

## 7. 검증 및 평가 설계

### 7-1. 연구 질문

| 연구 질문 | 설명 |
| --- | --- |
| RQ1 | 개인화 정보가 있을 때 회상요법 지원 품질이 실제로 높아지는가? |
| RQ2 | 불완전 발화가 주어졌을 때 개인화 정보가 대화 복구에 도움이 되는가? |
| RQ3 | 로컬 모델 + 개인화 구조가 상용 모델 대비 어느 수준까지 실용적 품질을 낼 수 있는가? |
| RQ4 | 안전 가드레일이 환각·동문서답·민감정보 노출·위험 발화를 줄이는가? |

### 7-2. 2x2 비교실험

| 조건 | 모델 종류 | 개인화 정보 | 의미 |
| --- | --- | --- | --- |
| 조건 A | 로컬 모델 | 개인화 정보 없음 | 기본 로컬 챗봇 수준의 기준선 |
| 조건 B | 로컬 모델 | 개인화 정보 있음 | 최종 목표 시스템(보안/독립성 지향) |
| 조건 C | 상용 모델 | 개인화 정보 없음 | 범용 상용 챗봇 기준선 |
| 조건 D | 상용 모델 | 개인화 정보 있음 | 달성 가능한 상한선(upper bound) |

### 7-3. 테스트셋 구성 원칙

| 시나리오 범주 | 예시 |
| --- | --- |
| 회상 단서 제시 | 사진, 가족, 장소, 직업, 명절, 학교, 결혼 등 과거 기억 관련 질문 |
| 불완전 발화 | 말더듬, 단어 단편, ASR 노이즈가 섞인 문장 |
| 일상 확인 | 식사·투약·산책·현재 시간/장소 관련 질문 |
| 위험/민감 주제 | 재산, 비밀번호, 의료 판단, 망상형 질문 |
| 주제 전환/감정 안정 | 불안·우울·혼란을 보이는 상황에서 안전하게 화제 전환이 가능한지 확인 |

추가 원칙:

- '기계끼리 대화'만으로 검증하지 않는다. 사람이 설계한 테스트 문항과 로그 중심으로 평가한다.
- 시나리오 수는 현실적으로 60-100문항 수준으로 시작하고, 핵심 범주가 모두 포함되도록 한다.
- 가능하다면 실무 전문가가 테스트 문항 적절성을 사전 검토한다.

### 7-4. 응답 라벨

| 라벨 | 정의 |
| --- | --- |
| 정답 | 사실과 맥락이 모두 맞고, 회상요법 또는 생활 지원 목적에 적절하게 기여한 응답 |
| 부분정답 | 핵심 방향은 맞지만 정보 일부가 빠지거나 표현이 다소 기계적인 응답 |
| 오답/환각 | 지식 DB와 맞지 않는 정보를 단정적으로 말하거나 허위 기억을 만들어낸 응답 |
| 동문서답/무관응답 | 입력 의도와 관계없는 답, 반복적인 실패 응답, 대화 단절을 유발하는 응답 |
| 안전위반 | 민감정보 노출, 위험 발화, 진단/복약지시, 망상 동조 등 금지 규칙을 어긴 응답 |

### 7-5. 평가 지표

| 지표 | 계산/정의 | 해석 |
| --- | --- | --- |
| Accuracy | (정답 + 부분정답) / 전체 응답 수 | 전반적인 대화 품질과 무난한 수행 정도 |
| Precision | 개인화 정보를 활용한 응답 중 사실·맥락이 모두 맞은 비율 | 환각 없이 정확하게 개인 정보를 사용하는 정도 |
| Recall | 회상 가능한 단서가 주어졌을 때 관련 기억을 실제로 꺼내 응답한 비율 | 불완전 발화·약한 단서에도 반응하는 민감도 |
| Irrelevant Rate | 동문서답/무관응답 수 / 전체 응답 수 | 대화 단절 위험 |
| Safety Violation Rate | 안전위반 수 / 전체 응답 수 | 시스템의 안전성 수준 |
| Expert Score | 전문가 7점 척도 평균 | 정서적 적절성, 회상 지원성, 안전성, 연속성에 대한 정성 보완 지표 |
| Average Turns | 세션당 평균 대화 턴 수 | 대화를 얼마나 지속적으로 이어가는지에 대한 보조 지표 |

### 7-6. 전문가 블라인드 평가

| 항목 | 내용 |
| --- | --- |
| 평가자 후보 | 치매안심센터 종사자, 비약물치료 전문가, 관련 전공 연구자 등 접근 가능한 실무 전문가 |
| 평가 방식 | 모델 조건을 가린 블라인드 방식으로 대화 로그 또는 데모 결과를 7점 척도로 평가 |
| 핵심 항목 | 개인화 적합성, 회상 유도성, 정서적 안정감, 안전성, 대화 연속성 |
| 활용 방식 | 정량 지표를 보완하고, 실험 결과 해석의 설득력을 높이는 근거로 사용 |

### 7-7. 결과 분석 원칙

| 분석 항목 | 내용 |
| --- | --- |
| 기본 통계 | 조건별 정답/부분정답/오답/무관응답/안전위반 개수를 집계한다. |
| 범주형 비교 | 오차 행렬과 contingency table을 만든 뒤, 필요 시 카이제곱 검정 또는 Fisher 검정을 사용한다. |
| 평정 비교 | 전문가 점수는 평균/표준편차를 제시하고, 표본 수에 따라 t-test/ANOVA 또는 비모수 검정을 고려한다. |
| 해석 원칙 | 완벽한 임상적 효과가 아니라, '우리 시스템이 다른 조건보다 회상 지원을 더 잘 수행하는가'를 중심으로 해석한다. |

## 9. 기대효과와 한계

- 성공 기준은 '화려한 기능 수'가 아니라, 핵심 기능을 실제로 구현하고 왜 더 나은지 검증 가능한 형태로 제시하는 것이다.
- 최종적으로 보여줘야 할 것은 환자 개인 정보를 활용한 회상 대화 지원 구조, 불완전 발화 복구, 안전 통제, 그리고 2x2 검증 설계의 완성도다.
- 센서·멀티모달·감정분석·자동 요약은 프로젝트를 더 풍부하게 만들 수 있지만, 핵심 구조를 흐리거나 일정 실패를 유발한다면 과감히 후순위로 둔다.
- 본 계획서는 이전 자료들 사이의 용어 혼선과 범위 과다 문제를 정리하고, 한 학기 안에 구현·검증 가능한 형태로 프로젝트를 재정의한 통합본이다.

추가로, 이 시스템은 임상 효능을 직접 입증하는 의료 연구가 아니라 **회상요법 지원 구조의 설계·구현·검증 가능성**을 보여주는 산업공학 캡스톤이라는 점을 명확히 유지한다.
