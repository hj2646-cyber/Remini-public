# 시연영상 5단계 진화 대본

> 본 시스템 (`ai-server/`, port 8000) 은 그대로. 시연판 (`performance/ai-server/`, port 8100) 에서 `config.yaml` 의 `active_preset` 만 바꾸며 촬영.

## 촬영 흐름 (권장)

1. **본 시스템은 끄지 마세요** — 영상 마지막에 비교용으로 켜둠 OK.
2. 시연판 시작: `bash performance/start.sh`
3. 브라우저: `http://<SERVER_IP>:8100/static/patient.html`
4. 좌상단에 `[1] 1단계: …` 라벨이 떠 있으면 정상.
5. preset 바꿀 때마다 `config.yaml` 의 `active_preset` 만 1→2→3→4→5 로 수정 후 `bash performance/restart.sh`.

**캡션 텍스트 (영상 자막)**: *"초기 시제품 — 대화만 가능. 환자가 또렷이 말하지 않으면 의사소통 불가."*

## 5단계 — 현재 시스템 (UI 검정 + 사진 작게 상단 200px + 보호자 폰 푸시)

**모델**: `remini-stage26-carecall:latest` (동일)
**보여줄 것**:
- 4단계 + 회상 사진 자동 트리거 ON
- 사진 카드 상단 200px (자비스 orb 안 가림)
- 책 4단계 점진 자극 + 사진 매개 회상
- ⭐ **위험 발화 감지 → 보호자 폰 PWA 잠금화면 푸시** (5월 13일 추가)

**대본 예시**:
1. 5턴 진행 → 자동 사진 트리거 → 상단에 사진 작게 나타남
2. 환자: "어머 이 사진…" → AI: "어떤 기억이 떠오르세요?"
3. (분할 화면 / 옆 폰) 환자 발화 "다 끝내고 싶어" → AI: 위로 + 1393 안내 → 동시에 보호자 iPhone 잠금화면에 "환자 위험 발화 감지" 푸시 도착

**캡션 텍스트**: *"+회상 사진 자동 매개 + 위험 발화 → 보호자 폰 실시간 푸시 — UI 는 마지막에 따뜻한 색감으로 진화 (다음 영상)."*

**사전 준비 (5단계 촬영 전 1회만)**:
1. 보호자 API (port 5000) 정상 동작 — `bash status.sh` 로 확인
2. 보호자 웹앱 (port 8082) cloudflared HTTPS 터널 띄움 — `bash demo-pwa.sh` (또는 직접 cloudflared)
3. iPhone Safari 로 보호자 웹앱 접속 → 공유 → "홈 화면에 추가" → 홈 아이콘으로 다시 열기 (standalone 필수)
4. 환자 선택 (성능판도 본 시스템과 같은 `aiUserId` 사용 — P001 등) → 알림 탭 → "잠금화면 푸시 알림 받기" 토글 ON → 권한 허용
5. "테스트 알림" 버튼 → 폰에 도착 확인하면 끝. 이후 재시작·재구독 불필요 (VAPID 키 `.env` 영구 박혀있음)
6. iOS 16.4+ 필수 (구버전은 PWA 푸시 X)

> 본 시스템과 성능판이 같은 caregiver API (port 5000) 향함. 같은 환자 ID 로 들어가면 둘 다 동일 디바이스로 푸시 감. 따라서 영상 촬영 시에는 성능판 (8100) 에서만 위험 발화하기 — 본 시스템 (8000) 에서 안 건드리면 중복 푸시 X.

## 트러블슈팅

- **포트 8100 이미 사용 중**: `bash performance/stop.sh` → 안 되면 `pkill -f 'port 8100'`
- **gemma4:31b 응답 느림**: 본 시스템에서 stage26 keep_alive=-1 로 잡혀있어 gemma4 cold prefill. 첫 응답 26초 정도 기다리기. 두 번째부터 빠름.
- **검은 UI 안 됨**: `performance/ai-server/web/ui-config.js` 가 `ui_theme: "dark"` 인지 확인. 없으면 `bash performance/restart.sh` 가 자동 생성.
- **사진 안 보임 (preset 5)**: `ai-server/data/reminiscence_photos/` 에 사진 0장이면 트리거 X. 본 시스템 data 와 symlink 되어 있으니 본 시스템에서 사진 드롭하면 됨.
- **KG 비어있어서 1·2단계 데모 안 됨**: P001 환자 KG 에 가족·고향 등 정보 사전 등록 필요. 보호자 앱으로 등록.
- **위험발화 푸시 안 옴 (preset 5)**:
  1. 보호자 API 로그 확인 — `tail -f caregiver/artifacts/api-server/logs/*.log` (또는 콘솔). `[alert push]` 라인이 떠야 함. 안 뜨면 → 환자가 보호자에 등록 안 됐거나 `aiUserId` 불일치
  2. `aiUserId` 확인 — 환자 화면 입장 ID (예: P001) 가 보호자 앱의 환자 등록 `aiUserId` 와 같아야 함
  3. push 구독 확인 — `curl http://localhost:5000/api/patients/<aiUserId>/push-subscriptions` 로 구독 디바이스 보기. 0건이면 폰에서 다시 토글 ON
  4. 잠금 상태 아닌 폰 사용 중일 때는 OS 가 silent 처리할 수 있음 — 폰 잠그고 위험발화 시도
  5. `.env` 의 `VAPID_PUBLIC_KEY` 와 보호자 앱에 박힌 공개키 같은지 확인 (다르면 모든 구독 무효)
